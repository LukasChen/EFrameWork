# EFrame UI Checklist

## Placement

- Page: `QuiPanel`
- Popup: `QuiPopUp`
- Tooltip or short hint: `QuiTooltip`
- Highest-priority overlay: `QuiTop`

## Files

- Runtime controller: `Assets/App/Runtime/UI/Controllers` or `Assets/Modules/<Name>/Runtime/UI`
- Runtime view wrapper: `Assets/App/Runtime/UI/Views` or module runtime UI path
- Prefab: `Assets/App/Res/UI/...` or `Assets/Modules/<Name>/Res/UI/...`
- Generated binding namespace: `EFramework.Generated.UI`
- Generated binding path: `Assets/App/Runtime/Generated/UI` or `Assets/Modules/<Name>/Runtime/Generated/UI`

## Lifecycle

- View access classes are generated by the UI Binding tool
- Controllers access the active generated View through `CurrentView`
- Static UI structure, layout, sliced-image assembly, nine-slice settings, button hierarchy, and visual states are authored in Unity prefabs
- Controllers handle event binding, data refresh, state switching, and necessary dynamic list/item instantiation
- Repeated runtime-generated elements use a prefab Template in the View prefab or a standalone Widget prefab
- `OnViewCreated()` / `OnViewDestroyed()` are used for instance-level binding and release
- `OnViewOpened()` / `OnViewClosed()` are used for per-open refresh and pause behavior
- Cached UI can close without releasing the generated View instance immediately

## Avoid

- Hand-created persistent top-level Canvas or EventSystem in scene content
- Large-scale `new GameObject` assembly for static UI in Runtime controllers
- Deep `transform.Find` in controller logic when `QUIBinding` can expose nodes
- Controller constructors that read game data or framework services before the UI is shown
- Caching controller state as if it were a reusable view instance
- Hand-writing normal business View wrappers that should be generated
- Saving or driving `UIViewHandle` directly from business code
- View constructors that load prefab assets directly from an `assetPath`
- Reintroducing a controller `View` facade instead of using `CurrentView`
