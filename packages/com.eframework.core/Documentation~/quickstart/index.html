Getting Started

第一次把 EFrame 接进一个 Unity 项目时，先走这条最短链路。

这页只覆盖最容易踩偏的入口：启动场景、`EFrameComponent`、`EFrame.Initialize()`、服务访问和第一批运行时能力。更细的 UI、Data、Editor 和 AI 细节分别去模块页看。

入口组件
`EFrameComponent` + `EFrameProcedureComponent`
静态入口
`EFrame.Current`
优先目标
确保初始化链正确，再开始业务功能开发
Minimum Path

最小接入路径

1. 把 `EFrameComponent` 放在启动场景

该组件会在 `Awake()` 里暂停 `EFrameProcedureComponent`，执行 `EFrame.Initialize(this)`，成功后再初始化并启动流程系统。

2. 只在初始化完成后访问服务

在启动链以外的业务代码里，优先通过 `Context.UI`、`Context.Data` 访问；只有外层入口用 `EFrame.Current.*`。

3. UI 走 Controller + Handle

当前 UI 契约是 handle-first，不要把 View 重新当作公开生命周期入口。

Startup Flow

初始化链路在做什么

  1. `EFrameComponent.Awake()` 确保存在 `EFrameProcedureComponent`。
  2. 启动协程 `FrameWorkInitialize()`。
  3. 调用 `EFrame.Initialize(this)`。
  4. 初始化 Addressables、Data、Audio、UI、Event、Coroutine、Vibration。
  5. 创建 `EFrameContext`，并绑定到 `EFrame.Current`。
  6. 成功后启用流程组件，并广播 `AppStartedEvent`。
yield return EFrame.Initialize(frameComponent);

if (!EFrame.LastInitializationResult.Succeeded)
{
    Debug.LogError(EFrame.LastInitializationResult.Message);
    yield break;
}

var ui = EFrame.Current.UI;
var data = EFrame.Current.Data;
Service Access

运行时服务访问模型

核心约束只有一条：`EFrame` 是静态入口，服务所有权在 `EFrameContext`。这意味着你应该把业务逻辑尽量放在能拿到 `Context` 的对象中，而不是全局到处直接取 `EFrame.Current`。

  • `EFrame.Current.UI`
  • `EFrame.Current.Audio`
  • `EFrame.Current.Data`
  • `EFrame.Current.Events`
  • `EFrame.Current.Assets`
