Synced AI Contract

AI 层在 EFrame 里不是附属说明，而是框架合同的一部分。

这一层负责把框架的运行时规范、编辑器规范、目录结构、资源约束、冷启动和升级流程同步给业务项目，让 Codex、Copilot 和 Claude Code 在项目里直接工作在正确上下文里。

项目侧同步前缀
`eframe-*`
项目侧自定义前缀
`project-*`
仓库维护前缀
`maintainer-*`
Layer Map

这层由什么组成

`AGENTS.md`

Codex 入口规则，镜像高层框架合同，并指向相关 skill。

`.github/copilot-instructions.md`

Copilot 的常驻总规则，承载 EFrame 的基础工程约束。

`.github/instructions/eframe-*.instructions.md`

同步到业务项目的短规则，保持稳定、通用、长期有效。

`.github/skills/eframe-*`

同步到业务项目的按需工作流，例如 UI、数据表、资源和 guideline audit。

Boundary

三类命名边界必须分清

`eframe-*`

框架托管、可同步到业务项目。业务项目不应手工 fork 这些文件。

`project-*`

业务项目本地 overlay，只写差异，不复制整份框架规则。

`maintainer-*`

仅框架仓库维护使用，不属于业务项目同步面，不能误发布成项目合同。

Workflow

接入和升级怎么走

.\tools\Initialize-EFrameColdStart.ps1 -TargetRoot "D:\YourUnityProject" -Force

.\tools\Initialize-EFrameAI.ps1 -TargetRoot "D:\YourUnityProject" -StatusOnly
.\tools\Initialize-EFrameAI.ps1 -TargetRoot "D:\YourUnityProject" -Force

冷启动面向新项目，AI 同步面向已有项目升级。两条链最终都依赖 `.github/eframe-ai.manifest.json` 作为同步版本信号。

When To Update

哪些变化必须联动 AI 层

Runtime / UI 合同变更

例如 `QUI`、`UIViewHandle`、`UIControllerBase` 的职责或模板边界改变。

Editor / 冷启动流程变更

例如初始化窗口、脚本、模板复制和生成产物发生调整。

目录、命名、资源入口变更

例如 `ResPath`、Addressables 分组、目录规范或命名规范变化。

发布与同步流程变更

变更 `.github` 规则、skills、同步脚本或 AI setup/release 文档时，要同步 bump manifest。
