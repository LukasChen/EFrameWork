Workflow Example

创建一个 UI 页面时，先搭 Controller 和 Binding，而不是先把业务逻辑塞进 View。

这条示例以当前 handle-first UI 契约为准。目标是从资源路径、View wrapper、Controller、按钮绑定到显示调用，串出一条最小可用链路。

Step 1

准备资源入口

先保证 UI prefab 有稳定资源路径，并通过 `ResPath` 或生成常量暴露给代码层。不要在 Controller 里散写裸字符串。

protected override string AssetPath => ResPath.Generated.UI.HomeView;
Step 2

写一个轻量 View wrapper

public sealed class HomeView : BindingViewBase
{
    public Button StartButton { get; private set; }

    protected override void OnBindingSet()
    {
        StartButton = Binding.transform.Find("Panel/StartButton")?.GetComponent<Button>();
    }
}

View 只负责把 `QUIBinding` 包装成强类型访问入口。不要让它重新承担公开生命周期或控制器职责。

Step 3

在 Controller 里绑定实例级行为

public sealed class HomeController : UIControllerBase<HomeView>
{
    protected override string AssetPath => ResPath.Generated.UI.HomeView;

    protected override void OnViewCreated()
    {
        base.OnViewCreated();
        AddButtonClickListener(CurrentView.StartButton, OnStartClicked);
    }

    protected override void OnViewOpened()
    {
        Context.Audio.PlaySfx("Audio/UI/Open");
    }

    private void OnStartClicked()
    {
    }
}

实例级监听放 `OnViewCreated()`，每次打开的刷新放 `OnViewOpened()`。缓存复用时，这两个时机的区别非常重要。

Step 4

显示页面

var controller = UIControllerBase.GetOrCreateInstance<HomeController>();
await controller.ShowAsync();

页面显示的公开入口应该在 Controller，而不是直接对 View 或 `QUIBinding` 做 open/close 操作。
