创建一个 DataTable 的关键不是定义模型，而是把改值入口、版本和结果诊断都留在表内。

这条示例覆盖默认数据、注册、读取、改值和保存。目标是让业务代码只依赖表的公共 API，而不是直接碰底层存储结构。

Step 1

定义数据模型和表

[Serializable]
public sealed class PlayerSettingsModel
{
    public bool MusicOn;
    public bool SfxOn;
}

public sealed class PlayerSettingsTable : DataTable<PlayerSettingsModel>
{
    protected override int CurrentVersion => 1;

    public bool MusicOn
    {
        get => Data.MusicOn;
        set => SetValue(ref Data.MusicOn, value);
    }

    protected override PlayerSettingsModel GetDefaultData()
    {
        return new PlayerSettingsModel { MusicOn = true, SfxOn = true };
    }
}
Step 2

注册表

EFrame.Current.Data.RegisterTable<PlayerSettingsTable>();
var table = EFrame.Current.Data.GetTable<PlayerSettingsTable>();

推荐在启动流程里统一注册，不要到处懒注册。这样加载和保存行为更稳定，也更容易审计。

Step 3

改值时只走表自己的 API

table.MusicOn = false;
table.Save();

var saveResult = table.LastSaveResult;
Debug.Log(saveResult.Message);

你应该读取 `LastSaveResult` / `LastLoadResult` 来判断结果，而不是单纯依赖控制台日志。

Step 4

需要升级时再引入版本迁移

当数据模型发生向前兼容变化时，通过 `CurrentVersion` 和 `Migrate(...)` 让旧存档迁移到新版本。迁移逻辑也应留在表内部，避免散落在业务代码里。
