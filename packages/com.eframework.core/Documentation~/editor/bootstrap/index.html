Project Bootstrap

Editor 侧最有价值的不是零散菜单，而是把冷启动和升级动作收敛成稳定入口。

EFrame 当前已经把项目初始化、Addressables 同步、模板导入、Audio 初始化、DOTween 前置条件整理成 Editor 工具链。文档页要做的是告诉你每个入口负责什么，而不是只罗列菜单名。

日常同步
Managed directory auto-sync + build preflight
目标
让新项目和升级项目都走统一路径
Strong Resource Convention

Managed resources should be placed, not hand-wired.

`Assets/App/Res`, `Assets/Scenes`, and `Assets/Modules` are EFrame-managed Addressables roots. The framework owns group selection, generated address, `eframe-managed` label, and stale entry cleanup for those directories.

`Sync Groups And Generate ResPath` opens the report window where projects choose which directory subtrees generate `ResPath.Generated`; import/move/delete automation and build preflight handle normal Addressables correctness.

Tool Map

核心入口怎么分工

`EFrameProjectInitializationWindow`

项目初始化总入口，负责冷启动、Addressables/ResPath、Audio、DOTween、StartUp 场景和初始模板导入。

`EFrameAddressablesSyncMenu`

作为资源地址修复/验证入口，重新同步托管 Addressables 分组，并按窗口中选择的目录生成 `ResPath.Generated.cs`，不触发完整初始化流程。

`EFrameUIBootstrapUtility` / `EFrameSampleUIPrefabUtility`

负责 UI sorting layer、示例 prefab、运行时必需资源模板的落地。

`EFrameAudioBootstrapUtility` / `EFrameDotweenBootstrapUtility`

负责运行前置资产和框架依赖的初始化，不建议让业务项目自己重复手工搭。

Recommended Usage

只重新导入示例 UI`Import Initial Templates`避免整套初始化重跑，只更新示例 prefab。
