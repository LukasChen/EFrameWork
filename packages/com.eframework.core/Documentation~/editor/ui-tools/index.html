UI Authoring

UI 编辑器工具的目标不是多一个 Inspector，而是把 `QUIBinding` 和 UI 生成约定固定下来。

当前 UI 编辑器能力主要围绕 `UIAutoBindingEditor` 和 `QScrollerEditor`。它们帮助你在 prefab 侧维护 binding、ViewConfig、生成访问类和滚动组件设置，减少手写绑定和命名漂移。

Main Tool

`UIAutoBindingEditor` 在做什么

ViewConfig 编辑

维护 `DefaultLayer`、`IsViewRoot`、`UsingCache`、`AnimationRootName`、`AnimationDuration` 等运行时配置。

组件树浏览

扫描 `RectTransform` 树并展示可绑定组件，让 prefab 结构和 binding 信息保持同步。

生成访问类

通过 `Generate Class` 生成访问类代码，减少手写 `transform.Find(...)` 的重复劳动。

验证与清理

提供 `Validate` 和 `Clear All`，用于检查绑定有效性和快速回到干净状态。

Usage

推荐工作流

  1. 先给 prefab 挂上 `QUIBinding`。
  2. 在 Inspector 中配置 `ViewConfig`，确定默认层级、缓存和动画根节点。
  3. 刷新组件树，选择需要暴露到访问类的节点和组件。
  4. 使用 `Generate Class` 生成访问类，再由 View wrapper 或生成类消费。
  5. 资源结构变化后重新 `Validate`，避免运行时拿到失效引用。
End-to-End Example

从 `QUIBinding` 到 View wrapper 的完整链路

  1. 在 prefab 根节点挂 `QUIBinding`。
  2. 在 `UIAutoBindingEditor` 中配置 `ViewConfig`，至少确定默认层级、缓存和动画根节点。
  3. 从组件树选择需要暴露的 Button、Text、Image 等组件。
  4. 点击 `Generate Class` 生成访问类，这个类继承 `BindingViewBase`，并在 `OnBindingSet()` 里缓存组件引用。
  5. 让业务 View wrapper 直接使用这份生成类，或者以相同模式手写一个轻量 View wrapper。
  6. 在 `UIControllerBase` 中通过 `TypedViewHandle.TypedView` 消费这些引用。

生成类的核心结构

public class HomeViewAccess : BindingViewBase
{
    public Button StartButton { get; private set; }

    protected override void OnBindingSet()
    {
        base.OnBindingSet();
        StartButton = Binding.transform.Find("Panel/StartButton")?.GetComponent<Button>();
    }
}

这和旧式“构造时传路径并直接承担生命周期”的 View 写法不同。当前生成模型明确围绕 `BindingViewBase + OnBindingSet()` 构建。

Controller Integration

再把生成类接进 Controller

public sealed class HomeController : UIControllerBase<HomeViewAccess>
{
    protected override string AssetPath => ResPath.Generated.UI.HomeView;

    protected override void OnViewCreated()
    {
        base.OnViewCreated();
        AddButtonClickListener(TypedViewHandle.TypedView.StartButton, OnStartClicked);
    }

    private void OnStartClicked()
    {
    }
}

关键点是：Controller 访问实时实例时应始终走 `TypedViewHandle.TypedView`，不要回退到已经被移除的 `controller.View` 习惯。

QScroller

`QScrollerEditor` 在补什么

`QScrollerEditor` 是在 Unity 自带 `ScrollRectEditor` 基础上补充框架特有字段，而不是重写一套完整滚动面板。它额外暴露的重点是：

字段作用
`m_snapHorizontalUnits`横向吸附单位设置。
`m_snapVerticalUnits`纵向吸附单位设置。
`OnSnapToHorizontalSegment`横向吸附完成后的 UnityEvent。
`OnSnapToVerticalSegment`纵向吸附完成后的 UnityEvent。
Boundary

这里要守住的边界

Do

把 binding 和 ViewConfig 信息留在 `QUIBinding` 侧；让生成代码服务于当前 handle-first UI 契约。

Don't

不要回到手写大量硬编码路径和运行时散绑定的旧模式；不要让生成模板重新引入旧 `View` facade 习惯。
