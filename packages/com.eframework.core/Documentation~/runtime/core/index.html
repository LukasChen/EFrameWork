Runtime Entry

Core 模块定义了 EFrame 的启动、上下文注入和服务聚合方式。

这一层不直接承载业务能力，但它决定了所有业务能力如何被初始化、如何被访问、以及在退出时如何被清理。理解 `EFrame`、`EFrameContext`、`EFrameComponent` 的职责，是后续所有模块页面的前提。

Flow

初始化时序

  1. `EFrameComponent.Awake()` 确保有 `EFrameProcedureComponent`。
  2. 暂停流程组件，等待 `EFrame.Initialize(this)` 完成。
  3. 创建 Asset、Coroutine、Data、Event、UI、Audio 服务。
  4. 组装成 `EFrameContext`，绑定到 `EFrame.Current`。
  5. 让 `EFrameComponent` 和运行时对象拿到 `Context`。
  6. 初始化完成后启用流程并广播启动事件。
Key APIs

关键 API 参数与返回值

`EFrame.Initialize(EFrameComponent component)`

参数类型说明
`component``EFrameComponent`当前启动场景中的框架宿主。必须非空，并提供 UI/Scene Camera 与 Procedure 依附对象。
返回值`IEnumerator`协程式初始化链，可由 Unity 生命周期直接驱动。

`EFrameContext.InjectInto(GameObject gameObject)`

项说明
输入任意 GameObject，方法会扫描其自身和子节点上的 `MonoBehaviour`。
作用将 `EFrameContext` 注入给实现了 `IEFrameContextAware` 的对象。
典型场景Addressables 实例化对象、运行时生成 UI 或模块对象时补齐上下文。

`ICoroutineService`

方法用途
`StartCoroutine(IEnumerator coroutine)`由框架宿主统一启动协程。
`DelayCall(float delayInSeconds, Action action)`延迟执行回调，适合轻量时序动作。
`CallNextFrame(Action action)`下一帧执行回调，适合初始化后回填或延迟绑定。
Best Practice

你应该怎么用

Do

让 `EFrameComponent` 成为启动场景唯一的框架初始化入口；在拿到 `Context` 的对象里优先使用实例上下文；在外层边界才使用 `EFrame.Current`。

Don't

不要在多个场景对象里重复初始化 EFrame；不要在初始化完成前预取服务；不要把 `EFrame.Current` 当作到处可用的全局状态。
