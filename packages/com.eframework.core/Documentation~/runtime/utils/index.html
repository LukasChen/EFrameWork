Utilities

Utils 不是主流程入口，但它们定义了很多常用的低层模式和约定。

这里的工具类跨度很大，从输入、对象池、时间、HTTP 到 UI 辅助都有。实际使用时应优先判断是否已有更高层的服务接口，只有在服务层不合适时再直接依赖工具类。

Representative APIs

代表性工具 API

`QInput.GetPrimaryPointerDown()`

项说明
返回值`bool`，在启用 Input System 时统一判断鼠标左键或主触点是否本帧按下。
用途适合轻量跨平台点击/触摸判断，不用在业务层重复分支 Mouse 和 Touchscreen。

`QInput.TryGetPrimaryPointerPosition(out Vector2 position)`

项说明
返回值是否成功取得当前主指针位置。
输出参数`position` 为屏幕坐标；若失败则返回默认值。

Guideline

使用原则

先看有没有服务层

例如资源加载优先 `IAssetService`，事件分发优先 `IEventService`，不要因为工具类直接可用就绕过框架抽象。

把通用逻辑留在工具层

工具类应保持通用，不要塞入强业务命名、模块特定路径或玩法常量。
