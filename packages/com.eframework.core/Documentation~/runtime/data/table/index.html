Model Boundary

`DataTable<T>` 的核心价值不是“包一层泛型”，而是把 dirty、迁移、加载结果和默认数据统一收口。

业务项目真正高频接触的是这一层。它要求你把字段修改收回到表内部，而不是把 `Data` 暴露给外部随手改。只有这样，`IsDirty`、`LastLoadResult`、`LastSaveResult` 和迁移策略才有一致语义。

表键
`Key` / `StorageKey`
状态
`IsDirty` / `IsLoaded` / `LoadedVersion`
诊断
`LastLoadResult` / `LastSaveResult`
Mutation

为什么建议把字段修改包回表内

方法作用
`SetValue(ref field, value)`只有值真正变化时才标记 dirty。
`Mutate(Func<T, bool> mutator)`把复杂修改收进一个统一入口，由返回值决定是否标 dirty。
`MarkDirty()`底层显式标记。通常由表内部受控调用，而不是对外开放乱用。
 
public sealed class PlayerSettingsTable : DataTable<PlayerSettingsModel>
{
    protected override int CurrentVersion => 2;

    public bool MusicOn
    {
        get => Data.MusicOn;
        set => SetValue(ref m_data.MusicOn, value);
    }

    protected override PlayerSettingsModel GetDefaultData()
    {
        return new PlayerSettingsModel
        {
            MusicOn = true,
            SfxOn = true
        };
    }
}

关键不是属性语法，而是所有改值路径都经过表自己，从而保住 dirty 语义。

Load & Migrate

加载时 DataTable 在做什么

有版本化 envelope

读取 `DataEnvelope<T>`，得到版本、时间和数据体。

旧版本

调用 `Migrate(data, fromVersion)`，迁移成功后更新到 `CurrentVersion` 并标记 dirty，等待后续写回。

未来版本

允许加载，但会记录 `FutureVersionLoaded`，提醒运行时版本落后于存档。

无存档或读取失败

回到 `GetDefaultData()`，并通过 `LastLoadResult` 明确说明是默认创建还是失败回退。

Override Points

子类最应该实现的扩展点

成员用途
`GetStorageKey()`声明稳定存档 key。必须非空。
`GetDefaultData()`提供无存档、回退或 reset 时的默认值。
`Migrate(T data, int fromVersion)`处理旧版本存档升级。
`OnInit()` / `OnDispose()`首次加载后做初始化，Dispose 时做清理，例如事件订阅解绑。
