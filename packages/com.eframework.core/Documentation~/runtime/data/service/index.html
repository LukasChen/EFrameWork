Orchestration

`IDataService` / `DataManager` 负责的是注册、批量加载保存和应用生命周期接线，而不是表内部业务语义。

数据系统里最上层的职责很明确：统一管理有哪些表、这些表什么时候加载、什么时候保存，以及在暂停和退出时触发什么保存策略。具体字段怎么变、什么时候标 dirty，不属于这里。

Key APIs

服务层 API

`T RegisterTable<T>() where T : IDataTable, new()`

行为说明
创建并注入存储内部 `new T()` 后会立即 `SetDataStorage(m_storage)`。
校验唯一性同时校验 `Key` 和 `StorageKey`，避免不同表写到同一份存档。
自动加载注册完成后立即 `table.Load()`，不是只登记不加载。
重复注册若同类型表已存在，直接返回已注册实例。

`GetTable<T>()`

通过类型名作为 key 获取已注册表。如果表未注册，`DataManager` 会记录错误并返回默认值。因此推荐在启动流程统一注册，不要依赖“先用再说”的惰性调用。

`SaveAll(bool forceFlush = false)` / `LoadAll()`

`SaveAll()` 会遍历所有表并转发 `forceFlush`。`LoadAll()` 会重新执行每张表的加载流程。它们本身不理解单张表的数据结构，只负责批量编排。

Lifecycle

DataManager 自动接了哪些应用事件

`AppPausedEvent`

调用 `SaveAll()`，只保存 dirty 表。

`AppQuitEvent`

调用 `SaveAll(true)`，强制冲刷，避免退出时漏写。

`Dispose()`

再次 `SaveAll(true)`，随后逐张 `Dispose()` 并清空注册表。

Boundary

服务层不该承担什么

应该做

注册、加载、保存、唯一性校验、应用生命周期接线。

不应该做

字段级变更、版本迁移细节、业务规则判断。这些应留在 `DataTable<T>` 内部。
