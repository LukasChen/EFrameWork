Persistence

Data 模块真正要解决的问题不是“怎么存”，而是“怎么稳定地知道这次存取发生了什么”。

EFrame 的数据层围绕 `IDataService`、`IDataTable`、`DataTable<T>`、`IDataStorage` 和结构化结果对象组织。它不鼓励业务直接拿裸对象随意改值，而是要求通过表自身的 dirty 语义和版本迁移入口来维护状态。

Core Types

模块职责分工

`IDataService` / `DataManager`

负责注册表、统一加载保存、在应用暂停或退出时触发保存链。

`IDataTable`

定义持久化表的稳定契约，包括 `StorageKey`、脏状态、加载状态以及最近一次保存/加载结果。

`DataTable<T>`

业务最常用扩展点。负责默认数据、迁移、脏标记和面向业务的安全修改入口。

`IDataStorage` / `JsonFileStorage`

底层存储实现。当前默认实现带备份和容错路径，支持结构化结果回传。

Key APIs

关键 API 参数与返回值

`IDataService.RegisterTable<T>()`

项说明
泛型约束`T : IDataTable, new()`。表必须可无参构造，并实现数据表契约。
返回值注册后的表实例。通常注册后立刻可以 `GetTable<T>()` 再次取得。
使用时机推荐在框架初始化后的启动流程中统一注册，而不是业务散点懒注册。

`DataTable<T>.Save(bool forceFlush = false)`

参数类型说明
`forceFlush``bool`即使表当前不是 dirty，也强制执行一次保存流程。
结果`LastSaveResult`保存后通过表状态读取。包含状态、原因码、版本号和消息，不依赖日志猜测。

`DataTable<T>.Load()`

结果分支说明
正常加载直接设置 `Data`，更新 `LoadedVersion`，记录 `LastLoadResult`。
旧版本迁移调用 `Migrate()`，迁移成功后标记 dirty，等待后续写回。
失败回退使用默认数据，保留结构化失败原因，避免只靠日志排查。
无存档创建默认数据，状态记为 `DefaultDataCreated`。
Recommended Pattern

推荐表写法

public sealed class PlayerSettingsTable : DataTable<PlayerSettingsModel>
{
    protected override int CurrentVersion => 2;

    public bool MusicOn
    {
        get => Data.MusicOn;
        set => SetValue(ref Data.MusicOn, value);
    }

    protected override PlayerSettingsModel GetDefaultData()
    {
        return new PlayerSettingsModel
        {
            MusicOn = true,
            SfxOn = true
        };
    }
}

关键点是把改值动作包进表内部，让 dirty 语义、版本迁移和结果对象都保留在统一模型里，而不是让外部直接随意改 `Data`。

Diagnostics

为什么这里专门强调结果对象

`DataLoadResult`

说明数据来自主文件、备份、旧版原始数据还是回退默认值，并给出原因码，适合 UI 和调试工具直接展示。

`DataSaveResult`

说明这次是实际写入、跳过未脏数据还是保存失败，避免“看起来没报错但其实没写文件”的灰区。
