Orchestration

`UIControllerBase` 管的是编排，不是 prefab 细节；它站在 Handle 上面，把显示时机和业务响应组织起来。

泛型版本 `UIControllerBase<TView>` 自动持有 `UIViewHandle<TView>`，负责在第一次显示时创建 View，在后续显示时复用，在关闭时区分“只是关闭”还是“彻底释放”。

控制器入口
`Show()` / `ShowAsync()` / `Hide()` / `HideAsync()`
View 访问
`TypedViewHandle` / `ViewHandle`
扩展点
`OnViewCreated` / `OnViewOpened` / `OnViewClosed` / `OnViewDestroyed`
Lifecycle Hooks

四个 Hook 的分工

Hook调用时机适合放什么
`OnViewCreated()`第一次创建 Handle / View 之后实例级绑定，例如按钮监听、一次性组件缓存。
`OnViewOpened()`每次成功显示之后每次进入页面都要刷新的 UI 状态。
`OnViewClosed()`每次关闭前停止轮询、结束临时状态、暂停页面行为。
`OnViewDestroyed()`实例真正释放前解绑、清理强引用、释放和实例寿命一致的资源。
Show & Hide

显示与关闭的真实流程

`Show()` / `ShowAsync()` 会先检查 `m_viewHandle` 是否存在且存活；如果没有，就通过 `CreateViewHandle(layer)` 创建，再触发 `OnViewCreated()`。随后调用 Handle 的 `Open` 或 `OpenAsync`，如果从未显示变成已显示，再触发 `OnViewOpened()`。

`Hide()` / `HideAsync()` 先判断当前是否在显示，再根据 `UsingCache` 决定只是关闭还是释放。也就是说，`OnViewDestroyed()` 只有在实例要真正释放时才会触发。

Helpers

控制器侧的便捷能力

方法用途
`AddButtonClickListener`统一按钮点击绑定，可选择先移除旧监听。
`AddToggleValueChangedListener`设置初值并绑定 Toggle 事件。
`AddSliderValueChangedListener`设置初值并绑定 Slider 事件。
`EnqueueToShow` / `EnqueueAsChild`接入全局 TaskQueue，把页面显示编排进队列。
Pattern

推荐写法

public sealed class HomeController : UIControllerBase<HomeView>
{
    protected override string AssetPath => ResPath.Generated.UI.HomeView;

    protected override void OnViewCreated()
    {
        base.OnViewCreated();
        AddButtonClickListener(TypedViewHandle.TypedView.StartButton, OnStartClicked);
    }

    protected override void OnViewOpened()
    {
        base.OnViewOpened();
        TypedViewHandle.TypedView.RefreshComponents();
    }

    private void OnStartClicked()
    {
    }
}

这里的关键不是继承本身，而是职责切分：Controller 只用 `TypedViewHandle.TypedView` 读写当前活着的 View，不自己承担实例化和释放规则。
