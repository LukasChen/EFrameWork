Sequence

这条时序图回答的是：一次 `ShowAsync()` 和 `HideAsync()`，到底是谁在什么时候做了什么。

当前 UI 契约的关键不是类名，而是调用顺序。Controller 决定时机，Handle 驱动状态，View 承接低层动作，QUI 负责宿主环境。下面这张静态时序图对应源码里的真实主链。

外层流程请求显示页面

Gameplay / Procedure 调用 `controller.ShowAsync(layer)`。

Gameplay / Procedure → UIControllerBase<TView>

Controller 决定是否首次创建

如果还没有存活的 `m_viewHandle`，就通过 `CreateViewHandle(layer)` 创建，并触发 `OnViewCreated()`。

UIControllerBase<TView> → QUI → BindingViewBase → UIViewHandle<TView>

QUI 创建 binding 和 view

`QUI.CreateBinding()` 实例化 prefab、注入上下文，`CreateView<TView>()` 再调用 `view.SetBinding(...)`，最终触发 `OnBindingSet()`。

QUI → BindingViewBase
4
Handle 进入 Opening

`OpenAsync()` 会 `KillTransition()`，调用 `PrepareForOpen(layer)`，再等待 `PlayOpenTransitionAsync()`。

UIViewHandle<TView> → BindingViewBase → QUI
5
Controller 收到“已显示”时机

当 Handle 成功变成 `IsShowing`，Controller 才触发 `OnViewOpened()`，做每次打开都要刷新的逻辑。

UIViewHandle<TView> → UIControllerBase<TView>
6
外层流程请求关闭页面

Gameplay / Procedure 调用 `controller.HideAsync()`，Controller 先按需触发 `OnViewClosed()`。

Gameplay / Procedure → UIControllerBase<TView>
7
Handle 执行关闭与释放决策

`CloseAsync()` 会调用 `PrepareForClose(false)` 并等待关闭过渡；若 `UsingCache` 为真则进入 `Closed`，否则 `Release()` 进入 `Released`。

UIControllerBase<TView> → UIViewHandle<TView> → BindingViewBase → QUI
8
Controller 按释放结果补收尾

只有实例真正释放时，Controller 才需要进入 `OnViewDestroyed()` 路径；只是缓存关闭时，不会重建实例级绑定。

Interpretation

看这张图时最容易踩错的点

`OnViewCreated()` 不是每次打开都触发

缓存启用时，只在第一次创建实例时调用；后续 reopen 只会走 `OnViewOpened()`。

`OnBindingSet()` 比 `OnViewCreated()` 更底层

它发生在 View 被注入 binding 的时候，通常比 Controller 的实例级初始化更早。

关闭不等于销毁

缓存模式下关闭只是 `Closed`，实例还活着；只有 release 路径才会走真正的销毁收尾。
