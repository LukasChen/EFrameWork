State Machine

`UIViewHandle<TView>` 把 View 从“一个对象”提升成“一个有状态的生命周期单元”。

Controller 不直接和 prefab 生命周期打交道，而是通过 Handle 驱动 `Created -> Opening -> Open -> Closing -> Closed / Released`。缓存复用、过渡打断和强制销毁都在这一层体现。

核心类型
`UIViewHandle<TView>`
状态枚举
`UIViewHandleState`
底层视图
`TypedView : TView`
State

状态迁移

状态含义
`Created`刚创建 Handle 和 View，但还未真正打开。
`Opening`正在执行打开流程或打开过渡。
`Open`已经可见且处于活动状态。
`Closing`正在执行关闭流程或关闭过渡。
`Closed`关闭后保留实例，用于缓存复用。
`Released`实例已释放，不可再使用。
Key APIs

打开、关闭和销毁

`Open(UILayer? layer = null)` / `OpenAsync(UILayer? layer = null)`

两者都会先 `KillTransition()`，然后调用 `TypedView.PrepareForOpen(layer)`。异步版本会等待 `PlayOpenTransitionAsync()`，并通过内部 `m_operationVersion` 防止旧操作在竞态下覆盖新状态。

`Close()` / `CloseAsync()`

关闭前都会进入 `Closing`，调用 `PrepareForClose(...)`。差异只在于是否等待关闭过渡。最终如果 `UsingCache` 为真，则 `DeactivateForReuse()` 并进入 `Closed`；否则 `Release()` 并进入 `Released`。

`CloseAndDestroy()`

无论 View 配置是否启用缓存，都会强制释放实例。这是“这次就是要丢掉实例”的显式语义，不要和普通 `Close()` 混用。

Properties

最常用的属性

属性说明
`TypedView`强类型 View 实例，也是 Controller 应优先访问的 View 入口。
`View`非泛型 `BindingViewBase` 视图，给统一抽象或接口消费。
`IsAlive`只要没进入 `Released` 且 View 未处于 disposed 状态，就为真。
`IsShowing`要求状态为 `Open/Opening` 且 GameObject 当前激活。
`UsingCache`从底层 View 推导出来，决定关闭后是否进入 `Closed`。
Usage

Controller 为什么应该依赖 Handle

var handle = Context.UI.CreateViewHandle<HomeView>(ResPath.Generated.UI.HomeView);
await handle.OpenAsync();

if (handle.IsShowing)
{
    handle.TypedView.RefreshComponents();
}

await handle.CloseAsync();

Controller 关注的是“何时创建”“何时打开”“何时回收”，而不是 prefab 是否在场景里。Handle 正是把这层时序收束起来的对象。
