Audio Runtime

Audio 模块负责的不是单次播放，而是框架级的音频路由、池化和事件驱动控制。

`AudioManager` 统一处理 Music、SFX、Mixer 音量控制和基础池化；`AudioEventManager` 负责配置驱动的事件式播放；`QVibration` 作为音频事件链的一部分，补齐触觉反馈。

播放服务
`IAudioService` / `AudioManager`
事件服务
`IAudioEventService` / `AudioEventManager`
资源约定
`AudioResourcePaths` + Resources 资产
Key APIs

关键 API 参数与返回值

`Initialize(bool musicOn = true, bool soundOn = true)`

参数类型说明
`musicOn``bool`初始化时音乐默认开关。
`soundOn``bool`初始化时音效默认开关。

`PlaySfx(string assetPath, float volume = 1f, float pitch = 1f)`

参数说明
`assetPath`音频资源路径。可由 `AudioClipAsset` 间接包装，也可直接指向音频资源。
`volume` / `pitch`本次播放级别的局部调节，仍会叠加全局 volume 和开关状态。

`PlayMusic(string assetPath, bool fade = true, float fadeDuration = AudioManager.K_fadeDuration)`

项说明
`fade`是否进行 crossfade 切换。
`fadeDuration`过渡时长，默认使用 `AudioManager.K_fadeDuration`。
内部结构`AudioManager` 维护 2 个独立 Music `AudioSource` 做切换。
Runtime Behavior

当前实现的关键行为

SFX 池

统一的音频池，带基础防抖和上限控制，避免短音频连续触发造成爆音和对象暴涨。

Music Crossfade

独立的双 `AudioSource` 切换模型，适合常见 BGM 平滑过渡。

Mixer 回退

若 Mixer 或分组缺失，仍可退回基础播放路径，但会输出警告提示初始化资产未准备完整。

Fallback Listener

如果场景里没有活动中的 `AudioListener`，会在 `AudioSourceHolder` 上添加一个兜底监听器。
