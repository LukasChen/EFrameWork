Persistence Backend

底层存储层最重要的不是“写成 JSON”，而是要明确这次数据究竟来自主文件、备份还是失败回退。

`JsonFileStorage` 负责文件读写、临时文件替换、备份回退和反序列化失败诊断；`DataLoadResult` / `DataSaveResult` 则把这些信息提升成可被上层直接使用的结构化结果，而不是只留在日志里。

JsonFileStorage

默认文件存储实现做了什么

写入路径

先写 `*.tmp`，再替换主文件；若平台不支持 `File.Replace`，退化到 best-effort 替换逻辑。

备份文件

主文件替换时会生成 `*.bak`，读取主文件失败时优先尝试从备份恢复。

Editor 与非 Editor 差异

非 Editor 环境会对字节流做 XOR 编码；Editor 下保持可读，方便调试。

存储位置

统一落到 `Application.persistentDataPath` 下，文件名基于 `StorageKey`。

Load Result

`DataLoadResult` 里有什么

字段说明
`Status`例如 `Loaded`、`Migrated`、`FallbackToDefault`、`FutureVersionLoaded`。
`ReasonCode`给出更细的失败或来源原因，例如 `LoadedBackup`、`DeserializeFailed`、`MigrationFailed`。
`Source`数据来自主文件、备份还是无来源。
`SourceVersion` / `TargetVersion`原始版本和当前期望版本，方便判断迁移路径。
`UsedLegacyData`是否回退读取了旧的裸数据格式。
`Message`可直接展示给调试 UI 或日志面板的文本说明。
Save Result

`DataSaveResult` 里有什么

字段说明
`Status`例如 `Saved`、`Skipped`、`Failed`。
`ReasonCode`说明是 `SavedDirty`、`SavedForceFlush`、`SkippedNotDirty` 还是底层异常。
`ForceFlush`这次保存是否来自强制冲刷路径。
`SavedVersion`本次保存时的表版本。
`Message`给调试工具或日志直接使用的人类可读说明。

这也是为什么文档一直强调“不要只看日志”。如果业务或调试 UI 需要向外展示存档状态，应优先读表上的 `LastLoadResult` / `LastSaveResult`。
