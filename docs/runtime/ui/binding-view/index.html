View Wrapper

`BindingViewBase` 是 prefab binding 的强类型包装层，不是业务生命周期入口。

这层负责接住 `QUIBinding`、读取 `ViewConfig`、缓存组件引用、处理 open/close 底层动作，并把真正的实例生命周期原语暴露给 `UIViewHandle<TView>` 和 `QUI`。业务代码不应该把它当成独立 UI 管理器来使用。

核心输入
`QUIBinding` / `ViewConfig`
核心输出
强类型组件访问入口
关键扩展点
`OnBindingSet()` / `RefreshComponents()` / `ValidateReferences()`
Construction

构造与绑定时机

入口语义
`BindingViewBase(QUIBinding binding)`直接从现成 binding 构造，不自动打开。
`BindingViewBase(string assetPath)`通过 `Context.UI.CreateBinding(assetPath)` 创建 binding，再应用 `ViewConfig`。
`BindingViewBase(string assetPath, UILayer layer, bool? useCache = null)`创建 binding 时就带层级覆盖和缓存覆盖。
`SetBinding(QUIBinding binding, string assetPath = null)`延迟注入 binding，并触发 `OnBindingSet()`。

当前框架更常见的路径不是直接 `new BindingViewBase(assetPath)`，而是 `QUI.CreateView<TView>()` 先创建实例，再调用 `SetBinding(...)`。这也是自动生成访问类围绕 `OnBindingSet()` 生成代码的原因。

State Helpers

它实际提供了哪些底层原语

`PrepareForOpen(UILayer? layer = null)`

激活 GameObject、挂到目标层级、广播 `UIOpenEvent`。

`PrepareForClose(bool killTransition, bool dispatchCloseEvent = true)`

广播关闭事件、从导航栈移除，并视情况终止 transition。

`DeactivateForReuse()`

用于缓存模式：停止 transition，禁用节点，但不释放实例。

`Release(bool forceDestroy = false)`

根据 `UsingCache` 和 `forceDestroy` 决定回收到缓存还是直接释放实例。

Override Points

子类最应该重写的点

方法推荐用途
`OnBindingSet()`拿到 binding 后缓存 Button、Text、Image 等组件引用。
`RefreshComponents()`需要重新扫描或刷新组件引用时使用。
`ValidateReferences()`在开发期快速检查关键引用是否完整。
`SetActive(bool active)`极少数需要特殊显隐行为时可覆盖。
 
public sealed class HomeView : BindingViewBase
{
    public Button StartButton { get; private set; }

    protected override void OnBindingSet()
    {
        base.OnBindingSet();
        StartButton = Binding.transform.Find("Panel/StartButton")?.GetComponent<Button>();
    }
}

这里的重点是“拿到 binding 后完成强类型映射”，而不是在 View 里自己决定何时打开关闭。

Boundary

这层不该承担什么

应该做

组件映射、配置承接、低层显隐原语、对 `QUI` / Handle 的生命周期配合。

不应该做

页面业务逻辑、按钮点击编排、弹窗结果流转、资源路径决策。那些仍然属于 Controller 或更上层流程。
