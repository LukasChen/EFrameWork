Handle-First UI

当前 UI 契约的核心不是“View 怎么写”，而是“生命周期归谁管”。

EFrameWork 的当前 UI 主链是 `Procedure / Gameplay -> UIControllerBase<TView> -> UIViewHandle<TView> -> QUI -> BindingViewBase`。控制器负责编排，句柄负责状态，`QUI` 负责宿主和缓存，View 保持轻量包装。

Responsibilities

四个核心类型分别负责什么

`QUI`

负责创建/复用 `QUIBinding`、创建 View/Handle、维护 layer、播放 transition、维护缓存和导航栈、绑定 UI Camera。

`BindingViewBase`

负责把 prefab binding 变成强类型访问入口，缓存组件引用，暴露底层生命周期原语；它不再是业务公开生命周期入口。

`UIViewHandle<TView>`

负责 `Created -> Opening -> Open -> Closing -> Closed/Released` 的状态转换，以及缓存型复用与强制销毁语义。

`UIControllerBase<TView>`

负责编排显示/隐藏时机、实例级绑定、每次打开刷新、每次关闭暂停和业务层的对外交互。

Key APIs

关键 API 细节

`IUIService.CreateViewHandle<TView>(string assetPath, UILayer? layer = null)`

参数类型说明
`assetPath``string`UI prefab 的资源路径。推荐使用 `ResPath` 或生成常量，不要散写裸地址。
`layer``UILayer?`可选覆盖层级。传 `null` 时使用 `QUIBinding` 里的默认层设置。
返回值`UIViewHandle<TView>`可复用的生命周期句柄。后续 open/close 都通过它进行。
 
var handle = Context.UI.CreateViewHandle<HomeView>(ResPath.Generated.UI.HomeView);
await handle.OpenAsync();

`UIViewHandle<TView>.OpenAsync(UILayer? layer = null)`

参数类型说明
`layer``UILayer?`本次打开时的层级覆盖。通常让 Controller 决定，不建议业务散写。
返回值`UniTask`等待打开动画完成。若 transition 被打断，最终状态仍由 handle 控制。

`UIViewHandle<TView>.CloseAsync()`

行为说明
缓存开启关闭后进入 `Closed`，实例和 binding 可复用。
缓存关闭关闭后进入 `Released`，释放 binding。
强制销毁`CloseAndDestroy()` 永远释放，不保留缓存。
Controller Pattern

推荐写法

public sealed class HomeController : UIControllerBase<HomeView>
{
    protected override string AssetPath => ResPath.Generated.UI.HomeView;

    protected override void OnViewCreated()
    {
        base.OnViewCreated();
        AddButtonClickListener(TypedViewHandle.TypedView.StartButton, OnStartClicked);
    }

    protected override void OnViewOpened()
    {
        Context.Audio.PlaySfx("Audio/UI/Open");
    }

    private void OnStartClicked()
    {
    }
}

实例级绑定放 `OnViewCreated()` / `OnViewDestroyed()`，每次打开刷新的内容放 `OnViewOpened()` / `OnViewClosed()`。不要把这两类逻辑混在一起，否则缓存复用时容易出错。

Do / Don't

必须守住的边界

Do

通过 Controller 和 Handle 管理打开/关闭；通过 `QUIBinding` 维护默认层级和缓存设置；通过 `EFrameSceneCamera` 决定 UI overlay 的宿主场景相机。

Don't

不要在业务层绕开 `QUI` 自己搭长期顶层 Canvas；不要把 View 当公开生命周期 API；不要手工轮询或直接篡改 UI camera stack。
