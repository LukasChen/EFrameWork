UI Host

`QUI` 是 UI 宿主、缓存池、层级容器和过渡调度者，不只是一个 service 门面。

当 Controller 或 ViewHandle 说“打开一个 View”时，真正负责实例化 prefab、注入上下文、选择层级、播放过渡、回收缓存和维护场景相机绑定的，是 `QUI`。

主要接口
`IUIService`
典型实现
`QUI`
相关类型
`QUIBinding` / `UILayer` / `EFrameSceneCamera`
Responsibilities

它直接负责的四件事

实例创建

`CreateBinding()` 用 Addressables 实例化 prefab，注入 `EFrameContext`，并要求根节点必须带 `QUIBinding`。

View 构造

`CreateView<TView>()` / `CreateViewHandle<TView>()` 负责把 binding 变成强类型 View 或 Handle。

缓存复用

`TakeBindingFromCache()`、`RecycleBindingToCache()`、`ClearViewCache()` 管理同资源路径下的复用池。

宿主环境

维护 `RootCanvas`、`UICamera`、`UILayer(...)`、过渡动画和 `EFrameSceneCamera` 绑定。

Key APIs

关键 API

`CreateBinding(string assetPath, UILayer? layer = null)`

参数说明
`assetPath`UI prefab 地址。推荐使用 `ResPath` 或生成常量。
`layer`可选父层级；不传时只创建 binding，后续由 View/Handle 挂到实际层级。

如果 prefab 根节点没有 `QUIBinding`，`QUI` 会立即释放实例并抛异常。这是框架用来约束 UI prefab 结构的硬边界。

`CreateViewHandle<TView>(string assetPath, UILayer? layer = null)`

内部流程是：`CreateBinding` -> `CreateView<TView>` -> `new UIViewHandle<TView>(assetPath, view)`。也就是说，Handle 只是生命周期包装器，实例来源仍由 `QUI` 控制。

缓存与释放

方法含义
`ReleaseBinding(assetPath, binding, useCache)`统一决定回收到缓存还是直接 `AssetManager.ReleaseInstance`。
`ClearViewCache(assetPath = null)`清空单个资源或全部缓存池。
`MaxCachedViewsPerAsset`单个资源路径的缓存上限，默认 8。
Camera & Layers

层级和场景相机

`UILayer` 决定 View 被挂到哪一层节点；`OpenBindingView()` 的职责就是把 View 挂到正确的层级 Transform。`RegisterSceneCamera()`、`UnregisterSceneCamera()`、`RefreshSceneCameraBindings()` 则把运行时场景相机接入 UI overlay 体系。

这也是为什么框架明确要求承载 UI overlay 的运行时场景相机挂 `EFrameSceneCamera`，而不是在业务代码里手工拼 camera stack。

Boundary

适合放在 `QUI` 的内容

应该放这里

实例创建、binding 释放、缓存池、层级容器、默认 transition 和场景相机桥接。

不该放这里

页面业务状态刷新、按钮响应、弹窗结果判断。这些仍然属于 Controller 或更上层业务流程。
